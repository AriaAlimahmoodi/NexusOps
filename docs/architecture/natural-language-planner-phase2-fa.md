# فاز دوم NexusOps — دقت معنایی برنامه‌ریز زبان طبیعی

## هدف

این فاز معنای شرط‌ها و عملگرهای کاربر را از متن فارسی/انگلیسی تا Plan معتبر MCP حفظ می‌کند. دامنه روی برنامه‌ریز قطعی Python و fallback قطعی در Workflow اصلی n8n هم‌زمان اعمال می‌شود؛ قرارداد ابزارها و موتور Analytics تغییر نمی‌کنند.

## اصلاحات

- حفظ چند شرط مستقل روی یک فیلد؛ برای نمونه بازه تقاضا با دو شرط gte و lte.
- پشتیبانی یکسان از عملگرهای gte، gt، lte، lt و نمادهای >=، >، <=، <.
- تبدیل مقایسه‌های معکوس عدد-فیلد به عملگر معادل فیلد-عدد.
- پشتیبانی از ارقام فارسی/عربی و جداکننده اعشاری نقطه/کاما.
- حفظ معنای OR در عبارت‌های صریح «یا/or» و AND در «و/and».
- رد fallback قطعی برای ترکیب تخت و مبهم AND/OR؛ در این وضعیت مدل باید ساختار گروه‌بندی روشن ارائه کند یا درخواست را مبهم اعلام کند.
- هم‌راستاسازی دستورالعمل Query Planner در n8n با قرارداد عملگرها و فیلترهای چندشرطی.

## سازگاری

- نام Datasetها، فیلدها، ابزارهای MCP، envelope پاسخ، محدودیت‌های فیلتر و مدل محلی تغییر نمی‌کنند.
- Exact-ID lookup و ابزارهای تخصصی Top-N همچنان اولویت قبلی را دارند.
- منطق پیچیده یا مبهم به fallback مدل محلی واگذار می‌شود؛ برنامه‌ریز قطعی نباید معنای سؤال را حدس بزند.

## آزمون‌های Regression

پوشش جدید شامل چند شرط روی یک فیلد، OR، ترکیب مبهم AND/OR، مقایسه معکوس و ارقام فارسی با اعشار کامایی است. قرارداد Workflow نیز وجود منطق معادل در validator و prompt را کنترل می‌کند.

## مرز پذیرش

تست‌های Python و قراردادهای Workflow باید در CI و محیط محلی اجرا شوند. اجرای زنده درخواست‌های OR/AND و مقایسه‌های مرزی در Chat Trigger اصلی پس از Import نسخه جدید Workflow لازم است؛ بررسی استاتیک به‌تنهایی صحت انتخاب Plan توسط Qwen3 را اثبات نمی‌کند.
