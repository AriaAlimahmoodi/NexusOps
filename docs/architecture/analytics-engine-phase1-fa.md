# فاز اول NexusOps — تکمیل موتور تحلیل

## دامنه

این فاز هسته تحلیل داده و برنامه‌ریز پرس‌وجو را تقویت می‌کند. توسعه Agentic چندمرحله‌ای و تحلیل تخصصی دانشگاه-بازار در فازهای بعدی باقی می‌مانند.

## تغییرات اصلی

- عملیات aggregate دو حالت دارد: تجمیع گروهی با یک یا چند فیلد group_by و تجمیع کلی با group_by خالی و حداقل یک metric.
- تجمیع کلی به‌صورت یک bucket با group خالی نرمال می‌شود. برای count_documents در حالت کلی، آداپتور Elasticsearch مقدار track_total_hits=true می‌فرستد تا شمارش به آستانه پیش‌فرض محدود نشود.
- نام مدل برنامه‌ریز از OLLAMA_MODEL خوانده می‌شود؛ مقدار پیش‌فرض qwen3:4b حفظ شده است.
- نرمال‌سازی فارسی/عربی، یکسان‌سازی ی/ک، ارقام فارسی و عربی، حذف نیم‌فاصله و علائم اعراب در برنامه‌ریز قطعی یکپارچه شده است.
- اعتبارسنجی برنامه تحلیل، فیلدهای ناشناخته، aliasهای نامعتبر، مقادیر ناسازگار با نوع فیلد، بازه‌های معکوس و ساختارهای بیش‌ازحد بزرگ را رد می‌کند.
- سقف‌های ساختاری: حداکثر ۳ بُعد گروه‌بندی، ۱۲ metric، ۵ معیار مرتب‌سازی، عمق فیلتر ۵، ۱۶ گروه و ۳۲ شرط؛ هر فهرست IN حداکثر ۱۰۰ مقدار.
- validator گردش کار n8n با قرارداد Python هم‌راستا شده و aggregate کلی را می‌پذیرد.

## سازگاری

- رفتار select و count تغییر معنایی نکرده است.
- تجمیع گروهی قبلی حفظ شده است.
- قرارداد پاسخ status/dataset_id/operation/result/metadata/warnings/error حفظ شده است.
- JOIN بین ایندکس‌ها اضافه نشده است؛ هر analytics_query همچنان فقط یک dataset را می‌خواند.

## اعتبارسنجی

آزمون‌های جدید تجمیع کلی، برنامه‌ریزی scalar، فیلد ناشناخته، عمق فیلتر و قرارداد n8n را پوشش می‌دهند. آزمون‌های زنده n8n/MCP/Elasticsearch باید پس از دریافت تغییرات در محیط محلی اجرا شوند.
