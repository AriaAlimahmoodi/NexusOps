# ابزار تشخیصی MCP Runtime — خارج از مسیر پذیرش معمول

## سیاست پروژه

پذیرش زنده‌ی NexusOps فقط از طریق Workflow اصلی Agent و مجموعه‌ی Full-System E2E انجام می‌شود. این فایل و Workflow متناظر آن، `workflows/nexusops-mcp-runtime-test-suite.json`، **مسیر پذیرش جداگانه نیستند** و در اجرای معمول Release Gate نباید اجرا شوند.

این ابزار صرفاً برای عیب‌یابی تخصصی نگه داشته شده است: اگر Full-System E2E در لایه‌ی MCP شکست خورد و لازم شد خطای پروتکل از خطای Planner یا پاسخ‌نویسی جدا شود، می‌توان آن را به‌صورت موردی اجرا کرد. نتیجه‌ی PASS این ابزار به‌تنهایی پذیرش محصول محسوب نمی‌شود.

## اجرای موردی برای عیب‌یابی

فقط زمانی که اجرای اصلی Agent خطای مبهمی در مرز MCP نشان داد:

1. Elasticsearch و MCP Server را اجرا کنید.
2. n8n را اجرا کنید.
3. فایل `workflows/nexusops-mcp-runtime-test-suite.json` را Import کنید.
4. Manual Trigger را اجرا کنید و خروجی `Evaluate Runtime Results` را بررسی کنید.
5. پس از تشخیص، به Workflow اصلی برگردید و پذیرش نهایی را فقط از مسیر Full-System E2E انجام دهید.

این Workflow داده‌ای را در Elasticsearch ایجاد، حذف یا به‌روزرسانی نمی‌کند.

## قرارداد پاسخ

- پاسخ‌ها با JSON-RPC ID متناظر می‌شوند؛ ترتیب خروجی HTTP به‌تنهایی مبنای correlation نیست.
- wrapperهای MCP از جمله `structuredContent` و JSON رشته‌ای در `result` نرمال می‌شوند.
- شناسه‌ی تکراری، پاسخ ناموجود یا خطای transport نباید به نتیجه‌ی خالی یا شمارش صفر تبدیل شود.
- خطای دیتاست نامعتبر باید یک envelope خطای ساختاریافته باشد.

## مرز اعتبار

این ابزار مستقیماً MCP را فراخوانی می‌کند و Ollama Planner، Domain Gate، Answer Writer و پاسخ نهایی را نمی‌آزماید. بنابراین هرگز جایگزین Full-System E2E نیست و نباید به‌عنوان یکی از چند آزمون پذیرش موازی استفاده شود.
