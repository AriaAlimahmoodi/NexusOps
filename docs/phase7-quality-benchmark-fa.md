# فاز ۷ — Benchmark کیفیت هوشمندی و پاسخ NexusOps

## هدف

فاز ۷ کیفیت پاسخ نهایی Agent را با مجموعه‌ای از درخواست‌های مرجع و معیارهای قابل‌اندازه‌گیری ارزیابی می‌کند. فاز ۶ ثابت کرد که مسیر اجرایی اصلی قابل رهگیری و زمان‌بندی است؛ فاز ۷ بررسی می‌کند که خروجی این مسیر تا چه حد درست، کامل، مستند به شواهد، هم‌زبان با درخواست و منطبق با محدوده سامانه است.

پذیرش زنده همچنان فقط از طریق Workflow اصلی `NexusOps-Agentic-Workflow` انجام می‌شود. Workflow موازی یا مسیر مستقیم MCP برای این Benchmark ساخته نشده است.

## وضعیت شروع فاز

این Commit زیرساخت اولیه Benchmark را اضافه می‌کند؛ هنوز هیچ نتیجه زنده‌ای برای کیفیت مدل ثبت نشده است. امتیاز نهایی فقط پس از اجرای محلی کاربر و بررسی گزارش واقعی قابل اعلام است.

## ابعاد ارزیابی

1. **دقت factual:** تطبیق شناسه‌ها، نام‌ها و مقادیر عددی پاسخ با داده مرجع فعلی.
2. **کامل بودن:** پوشش همه بخش‌های درخواست، تعداد موارد خواسته‌شده و ارائه ساختار مناسب.
3. **سازگاری زبانی:** فارسی ماندن پاسخ فارسی و انگلیسی ماندن پاسخ انگلیسی.
4. **اتکا به شواهد و محدوده:** بیان شاخص مورد سؤال، حفظ محدودیت داده و پرهیز از ادعای پشتیبانی‌نشده.
5. **قابلیت اتکا:** نبود خطای اجرا، پاسخ ناقص یا شکست پنهان‌شده.

هر معیار امتیاز و سطح بحرانی بودن مستقل دارد. شکست یک معیار بحرانی، حتی با امتیاز عددی بالا، همان سناریو را مردود می‌کند.

- هر سناریو از ۰ تا ۱۰۰ امتیاز می‌گیرد.
- حداقل امتیاز هر سناریو: ۸۰.
- حداقل میانگین کل: ۸۵.
- تمام معیارهای بحرانی باید قبول شوند.
- کل مجموعه باید اجرا شود؛ اجرای بخشی از سناریوها پذیرش کامل نیست.
- گزارش شامل امتیاز هر سناریو، معیارهای قبول/رد، ابعاد کیفیت، متن پاسخ و مدت‌زمان درخواست است.

این Benchmark از ارزیاب زبانی یا API پولی استفاده نمی‌کند. ارزیابی نسخه اول قطعی و مبتنی بر مقادیر، عبارات، زبان و ساختار مورد انتظار است.

## محدودیت اعتبار

بررسی کلمه، عدد و ساختار به‌تنهایی معادل قضاوت انسانی درباره کیفیت استدلال نیست. ممکن است پاسخ از نظر معنایی اشتباه باشد ولی بخشی از معیارهای متنی را بگذراند؛ یا پاسخ درست با عبارت‌بندی متفاوت از یک معیار واژگانی عبور نکند. به همین دلیل گزارش باید همراه با بازبینی نمونه پاسخ‌ها و تطبیق اعداد با Kibana بررسی شود.

این نسخه Benchmark ترتیبی است و هم‌زمانی، ترتیب Turnهای یک مکالمه، fault injection یا عملکرد بازیابی را اندازه نمی‌گیرد.

## اجرا

پس از Pull شاخه:

```powershell
python -m py_compile scripts/run_phase7_quality_benchmark.py tests/test_phase7_quality_benchmark.py

python -m pytest -q tests/test_phase7_quality_benchmark.py

python scripts/run_phase7_quality_benchmark.py `
    --base-url http://127.0.0.1:5678 `
    --timeout 300 `
    --report reports/phase7-quality-baseline.json
```

اجرای یک سناریو برای عیب‌یابی:

```powershell
python scripts/run_phase7_quality_benchmark.py `
    --base-url http://127.0.0.1:5678 `
    --case Q04 `
    --report reports/phase7-q04-diagnostic.json
```
