# اجرای پوشش برنامهٔ درسی طبق سند ۰٫۲

مسیر جدید دادهٔ CSV یا JSON محلی را با Adapter مشترک می‌خواند. نگاشت صریح، نام فیلدهای ورودی را به قرارداد `curriculum_catalog` تبدیل می‌کند. جدول معادل‌سازی نوع درس و واژه‌نامهٔ مهارت باید در تنظیمات منبع مشخص باشند. برای CSV، ستون مهارت باید آرایهٔ JSON باشد. `[]` یعنی نبود مهارت پس از بررسی و سلول خالی یعنی نبود شواهد.

برای هر اجرا یک `program_id`، رشته و مقطع مشخص کن. فهرست دروس اجباری باید از یک مرجع مستقل ثبت شود تا بتوان نبود یک درس را تشخیص داد. یک درس با شناسهٔ تکراری یا با نوع نامشخص، مهارت فاقد معادل در واژه‌نامه، تعلق به برنامهٔ دیگر یا فهرست ناقص، محاسبه را متوقف می‌کند. نبود تعداد واحد، شاخص مکمل را نامحاسبه‌پذیر می‌کند.

نمونهٔ قابل اجرا و قرارداد نگاشت در [فایل تنظیمات نمونه](../tests/fixtures/curriculum-coverage.json) است.

```powershell
python -m scripts.compute_curriculum_coverage --config tests/fixtures/curriculum-coverage.json
```

خروجی نمونه پوشش بر اساس درس را ۵۰٪ و پوشش بر اساس واحد را ۴۰٪ گزارش می‌کند. درس اختیاری نمونه در هر دو شاخص کنار گذاشته می‌شود.

برای دادهٔ واقعی، یک تنظیمات جدا بساز و محل فایل، مشخصات گردآوری، نگاشت بررسی‌شده، وضعیت اجباری یا اختیاری، شناسه‌های مهارت و فهرست معتبر دروس اجباری را مشخص کن. `source.uri` می‌تواند نسبت به فایل تنظیمات آدرس‌دهی شود. فرمت JSON از گزینه‌های مبدل فعلی، از جمله `"mode": "array"` برای آرایهٔ JSON، استفاده می‌کند.

```powershell
python -m scripts.compute_curriculum_coverage --config <config.json>
python -m scripts.compute_curriculum_coverage --config <config.json> --apply
```

`--apply` برای منبع واقعی، دادهٔ استاندارد برنامه را پس از اعتبارسنجی در `curriculum_catalog_real` منتشر می‌کند. اسناد هر نسخهٔ ورودی با `collection_batch` متمایزند. برای مشاهدهٔ یک نسخه، Alias را همراه با `collection_batch` گزارش فیلتر کن. صورت، مخرج، واحد، نسخهٔ فرمول، شناسهٔ برنامه و شواهد منشأ در خروجی محاسبه ثبت می‌شوند.

ذخیرهٔ نتایج در ایندکس مستقل، شاخص‌های تقاضا و عرضه و اتصال به Planner، MCP و n8n در مرحلهٔ بعدی طراحی و پذیرش سند قرار دارند.
